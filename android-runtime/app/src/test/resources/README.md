# Smart Turn numerical fixtures

`smartturn_golden.pcm` contains no speech, recording, or synthesized voice. It is eight seconds of
16 kHz mono signed little-endian PCM16: five seconds of zeros followed by three seconds of a swept
tone, a fixed tone, and deterministic broadband noise with a smooth envelope. The PCG64 seed is
20261014. The complete waveform formula lives in `tools/generate_turn_fixture.py`.

The generator passes that PCM through Transformers' independent NumPy
`WhisperFeatureExtractor(chunk_length=8)` with `do_normalize=True`, matching the runtime's waveform
normalization. `smartturn_golden.f32` stores the resulting 80 × 800
little-endian float32 values in row-major order. It then runs the existing bundled ONNX model using
Python ONNX Runtime's CPU provider. `smartturn_golden.json` records the reference probability
from that run, dependency versions, shapes, and SHA-256 hashes. The model is unchanged.
PCM and metadata are also copied to `src/main/assets` for the optional device self-test.

From the repository root, with Python 3.11 or later and the pinned dependencies installed in a
temporary virtual environment:

```powershell
python -m pip install -r tools/turn-fixture-requirements.txt
python tools/generate_turn_fixture.py
python tools/generate_turn_fixture.py --check
```

Generation uses only local mathematics and the bundled model; it does not download models or call
speech services. The NumPy feature-extraction backend is forced even if PyTorch is installed.
`--check` verifies every generated byte without modifying the fixtures; use the pinned environment
when reproducing them.

Tests retain the direct-DFT FFT comparison, constant-prefix optimization comparison, reference-feature
error thresholds, reference-model probability tolerance, and PCM-to-model probability comparison.
They additionally verify fixture/model hashes and agreement between packaged copies. These are
numerical regression tests. Non-speech input does not establish conversational turn-detection accuracy;
real speech and physical-device qualification remain separate work. JVM inference tests explicitly
skip if the host cannot load the native ONNX library, while DSP/hash tests still run.
